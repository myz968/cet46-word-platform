## 1. 交付边界（先说清楚，避免误解）

- 正式访问地址 = **你部署后的 HTTPS 网址**，例如 `https://words.example.com/` 或 `https://username.github.io/cet46/`。
- 不是 `http://10.x.x.x:5180`，也不是 `http://192.168.x.x:5180`。**任何局域网地址都不是正式访问地址。**
- 桌面版 Windows exe 和手机版 H5 是**两套独立程序、两套独立数据**，互不同步、互不影响。
- 正式交付**不需要**用户运行 `fix-firewall-5180.bat`，也不需要"电脑开着服务"。
- 纯静态方案：没有后端、没有数据库服务、没有 API 服务器，只有一堆静态文件。

## 4. 本地存储（不绕弯子）

**进度存在哪里**：全部存在**手机浏览器的 IndexedDB**，数据库名 `cet46_h5`，7 个对象仓：

| 仓 | 内容 |
| --- | --- |
| `words` | 词库缓存（懒加载，进哪档下哪档） |
| `answerRecords` | 每一次作答 |
| `wrongWords` | 错题本 |
| `reviewTasks` | 艾宾浩斯复习任务 |
| `stageRecords` | 每次闯关记录 |
| `userStages` | 每关最好正确率 / 挑战次数（**这就是"闯关进度"**） |
| `meta` | 词库版本、各难度导入状态 |

业务代码**没有使用 `localStorage` / `sessionStorage`**（`src/db/index.js` 注释里说明了为什么不用 localStorage：容量小、同步写会卡手机）。数据按浏览器**同源策略**隔离，域名就是隔离边界。

| 情况 | 会发生什么 |
| --- | --- |
| 换浏览器（Chrome → Safari） | 全新空进度，等于换了个账号 |
| 换手机 / 换电脑 | 全新空进度 |
| 清理该站点的浏览器数据 / 清缓存时勾选「站点数据」 | 进度**全部清空**，且不可恢复 |
| 无痕 / 隐私模式 | 关闭窗口即清空，**不建议用** |
| 换部署域名或换子目录（如从 `/cet46/` 换到 `/words/`） | 同源变了，进度会变成新的空库（**所以正式域名定了就别随便换**） |
| 正常退出浏览器、关机、重启手机 | 进度保留 |
| 卸载/重装浏览器 | 通常清空 |

**跨设备同步：不支持。** 单机单用户，`USER_ID` 固定为 1，没有账号系统、没有服务端、没有上传接口。桌面 exe 与 H5 之间也**不互通**。这一点必须写给用户，不能假装支持。

替代方案（本次未实现）：若将来要同步，需要新增后端 + 账号体系 + 冲突合并；当前纯静态方案做不到。

## 5. PWA 与「添加到主屏幕」

| 检查项 | 结论 |
| --- | --- |
| manifest 完整性 | ✅ `id / name / short_name / description / lang / start_url / scope / display=standalone / orientation / theme_color / background_color / categories / icons` 齐全；相对路径写法，子目录可用 |
| 图标齐全 | ✅ 192×192、512×512、maskable 512×512、apple-touch 180×180、favicon.svg，实测 PNG IHDR 尺寸与声明一致、文件头合法 |
| HTTPS 下「添加到主屏幕 / 安装应用」 | ✅ 具备条件（manifest + SW + HTTPS）。**注意：必须 HTTPS**（`localhost` 是唯一例外）；用 `http://` 局域网地址时不能安装，这正是之前局域网调试版只能加书签的原因 |
| Service Worker 注册 | ✅ 本地 127.0.0.1 安全上下文实测 `activated`；`sw.js` 随产物发布，scope 自动适配子目录 |
| 缓存策略 | 导航请求网络优先 / 断网回退 index.html；词库缓存优先；其它静态资源 stale-while-revalidate；install 时解析 index.html 预缓存带哈希的 JS/CSS，页面首次加载后再补缓存懒加载分包 |

**哪些内容支持离线（不夸大）**：
- ✅ 已经打开过的页面外壳、JS/CSS、图标
- ✅ **已经点进去下载过**的那一档词库（写入 IndexedDB 后完全离线）
- ✅ 全部学习数据（本来就在本地，从不联网）
- ✅ 断网后继续闯关、答题、看错题本、看报告

**哪些内容不支持离线**：
- ❌ **从未点开过的难度**——词库是按需分档下载的，没下过就断网，进不去那一档（这是为了首屏不下载 800KB 的设计取舍，不是 bug）
- ❌ **第一次访问之前**——必须先联网把站点和 SW 装下来
- ❌ 不支持 Service Worker 的浏览器（如部分微信内置浏览器）没有离线能力，但联网时仍可正常使用
- ❌ 应用**更新**需要联网；改了静态资源必须手动改 `public/sw.js` 里的 `VERSION`，否则老用户一直命中旧缓存

结论：**是"离线可用的 PWA"，不是"完全离线的原生 App"**。首次访问和未访问过的难度必须联网。

### ④ 推荐的静态托管方式
选型前先确认满足上表 6 个条件。三类方案：

| 方案 | 说明 | 适用 |

### ⑤ 上传 `dist` 的具体步骤（通用）
1. 本地执行 `npm run build`，确认 `dist/` 里有 `index.html` 且同级有 `assets/`、`data/`、`icons/`、`sw.js`、`manifest.webmanifest`、`.nojekyll`。
2. 在托管平台创建站点 / 存储桶，开启「静态网站托管」，拿到 HTTPS 访问域名。
3. 把 **`dist` 里面的全部内容**（含隐藏文件 `.nojekyll`）原样上传到站点根目录；若要用子目录，就传到 `站点根/cet46/`，保持同样的相对结构。若平台支持「上传 zip 自动解压」，可直接传 `dist.zip`（已含隐藏文件，避免漏传）。注意：隐藏文件 `.nojekyll` 在网页/FTP 上传时最容易被漏掉，GitHub Pages 少了它会白屏。
4. 按第 ③ 项配置 MIME 与缓存头（多数平台默认已正确；`.webmanifest` 是最容易出错的一个）。

### 与 `dist.zip` 的差异（重要，别混用）

`mobile/dist/` 与 `mobile/dist.zip` 保持**纯净通用**，供上传到 COS / GitHub Pages / Nginx 等标准静态托管使用。已上线的实例为了「配置 MIME 与缓存头」+ 适配该平台的 cookie 鉴权，单独有一个部署副本 `deploy-site/`，差异仅三处：

| 项 | `dist` / `dist.zip` | `deploy-site/`（已上线实例） |
| --- | --- | --- |
| `server.js` | 无 | 新增：零依赖 Node 静态服务，显式设置 MIME 与 `Cache-Control`，监听 `PORT`、绑定 `0.0.0.0` |
| `package.json` | 无 | 新增：仅声明 `start: node server.js` |
| `index.html` 的 manifest link | `<link rel="manifest" href="./manifest.webmanifest" />` | 多一个 `crossorigin="use-credentials"` |

**为什么 `index.html` 只在部署副本改**：浏览器拉 `<link rel="manifest">` 默认 `credentials: omit`，而该分享链接靠 cookie 鉴权，会导致 manifest 被网关 403、PWA 装不到主屏幕（实测首轮确有 2 条 403 + 2 条 manifest 报错）。加 `use-credentials` 后需服务端回显 `Access-Control-Allow-Origin`（具体 origin，非 `*`）+ `Access-Control-Allow-Credentials: true`。但标准静态托管通常不返回这些 CORS 头，若把该属性写进 `dist`，反而会让正式托管的 manifest 加载失败。因此**只在部署副本适配，纯净版不带此属性**。

业务代码（首页 / 关卡 / 答题 / 错题 / 复习 / 报告 / 词库 / IndexedDB）**零改动**。
