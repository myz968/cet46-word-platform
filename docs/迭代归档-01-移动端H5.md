## 一、本次迭代要解决的问题

桌面版是 Windows exe，只能在电脑上用。真实背单词场景大量发生在通勤、排队、睡前这些碎片时间，学生手上只有手机。
目标是在手机浏览器里直接打开就能背单词，**不装 App、不连电脑、断网也能用**。

硬性约束（来自需求方，全部满足）：

| 约束 | 是否满足 | 落地方式 |
| --- | --- | --- |
| 后端尽量复用、不重构原逻辑 | ✅ 未改后端任何代码 | H5 阶段一根本不调后端，词库与数据都在本地 |
| 桌面 exe 保持独立可用、不能被改坏 | ✅ 桌面端业务代码零改动 | 新建独立工程 `mobile/`，与 `frontend/` 完全隔离 |
| 响应式适配安卓 / iPhone 浏览器 | ✅ 360 / 390 / 430 三档实测 | 移动优先 CSS + `env(safe-area-inset-bottom)` 适配刘海屏 |
| 操作逻辑与桌面端一致 | ✅ 规则逐条复刻 | 每关 20 词、60% 通关、艾宾浩斯 0/1/2/4/7、错题累计 |
| 第一阶段不做电脑↔手机同步 | ✅ 未做 | 双方数据各自独立，README 已明确说明 |
| 离线优先 | ✅ 断网可用 | 词库存 IndexedDB，静态资源走 Service Worker |
| UI 与桌面端统一、学生能上手 | ✅ 同一套配色（#409eff 主色 / #f5f7fa 背景） | 不引组件库，自写轻量样式，无花哨动画 |
| 不打包安卓 APK | ✅ 未做 | 只交付浏览器 H5 |

## 二、四个关键选型（需求方拍板结果）

开工前按「不许自行决定」的要求列了选项，最终选择与理由：

| 决策点 | 选定方案 | 理由 |
| --- | --- | --- |
| 数据架构 | **纯本地离线模式** | 后端和 exe 一行不用改；手机打开即用，断网可学；符合「降低复杂度」 |
| 代码组织 | **新建独立 `mobile/` 目录** | 与 `frontend/` 零耦合，杜绝改坏已调好的桌面答题页 |
| 词库加载 | **按三级拆成 3 份 JSON 懒加载** | 进哪档下哪份（214 / 206 / 359KB），首屏最快、省流量，下载后进 IndexedDB 不再重复拉 |
| PWA | **基础页面完成后再加** | 按优先级 ①核心流程 → ②错题/复习 → ③报告 → ④PWA 推进，最后补 PWA 不影响前面验收 |

未选的方案与原因（备查）：

- 连现有 SpringBoot 后端：手机必须和电脑同局域网并手填 IP，电脑关机即不可用，违背离线优先。
- 双模式（先探测后端、失败降级本地）：状态同步分支多，本期出 bug 概率最高。
- 改造 `frontend/` 做一套响应式：省一份代码，但必然改动已调好的 `QuizView` 等页面，与「不能改坏桌面端」直接冲突。
- 5547 词打成一个整包 / 每级只内置 300 词：前者首屏等一次大下载，后者把已补齐的词库成果砍掉大半。

## 四、与桌面端的关系（硬约束的落地证据）

本次迭代改动的文件，除去 `mobile/` 与产物，只有：

```
README.md                        文档
docs\词库扩充指南.md              上一轮补词库的文档（时间戳早于 H5 开工）
scripts\start-mobile-dev.bat     新增
scripts\start-mobile-web.bat     新增
```

`backend\`、`frontend\src\`、`desktop\` 源码均无改动。
`desktop\release\` 下两个 exe 仍是上一轮补完词库后打的包（131MB / 139MB），未重新打包、未受影响。

判断标准很简单：**桌面版的启动链是「exe → 内置 JRE → jar → 内置 SQLite」，这条链上没有任何一个文件被碰过**，所以桌面版行为与本次迭代前完全一致。

## 五、规则一致性（H5 复刻了桌面端什么）

| 规则 | 桌面端（后端） | H5（`mobile\src\core\`） |
| --- | --- | --- |
| 每关词数 | `app.level-size: 20` | `LEVEL_SIZE = 20` |
| 通关线 | `PASS_ACCURACY = 0.6` | 同值，同一判定 |
| 题型 | EN2CN 四选一 / CN2EN 手敲 | 同（四选一选项从同难度其它词取干扰项，保证答案唯一） |
| 答错 | 入错题本 + 当天进复习队列 | 同 |
| 错题记录 | `UNIQUE(user_id, word_id)`，重复错累加次数 | `[USER_ID, wordId]` 作主键，累加 `wrongCount` |
| 艾宾浩斯 | 0 / 1 / 2 / 4 / 7 天 | 同间隔表，`plusDays` 推进 |
| 掌握条件 | 复习阶段满 5 次 | 同 |
| 关卡进度 | 记录最高正确率与通过状态 | 同，列表页同样显示「未通过 / 已通过 / 满分」 |
| 报告字段 | 正确率 / 用时 / 答对数 / 新增生词 | 同 |
| 词库分级 | 5547 词（1630 / 1488 / 2429） | **完全相同的 5547 词**，由 `build-words.mjs` 从后端 JSON 直接导出 |

对应关系：SQLite 的 7 张表 → IndexedDB 的 6 个对象仓（去掉 `t_user`，H5 无账号体系）。
这么做是为将来若要做「电脑↔手机同步」，字段已经能一一对上，不用重新设计数据结构。

## 七、已知限制（不是 bug，是有意为之）

| 限制 | 说明 |
| --- | --- |
| 手机与电脑数据不互通 | 阶段一明确不做同步。换设备只是进度不接着，学习体验不打架 |
| PWA 装机需 https 或 localhost | 浏览器硬规定。局域网 http 下功能与数据全部正常，只是不能加桌面 |
| 首次进入某难度要下载 200~360KB | 之后写入 IndexedDB，不再重复下载；断网前需先联机进过一次 |
| 清浏览器数据 = 清空学习记录 | H5 没有账号体系，数据归属就是「这个浏览器」 |
| 无痕模式关掉即清空 | 属浏览器行为，README 已提示 |
| 未打包 APK | 按需求本期只做浏览器 H5 |

## 八、如何重建（换机器 / 重新出包）

```bat
:: 1. 装依赖（只需一次）
cd /d <仓库根>\mobile
npm install

:: 2. 若后端词库有变动，重新导出三级 JSON（否则跳过）
node scripts\build-words.mjs
npm run check                 :: 自检 5547 词 / 无重复 / 无缺字段

:: 3. 出包
npm run build                 :: 产物在 mobile\dist
npm run serve                 :: 起 5180 服务，终端会打印手机可访问地址
```

改了静态资源后要同步把 `public\sw.js` 的 `VERSION` 加一，否则手机端会一直命中旧缓存。

## 十、一句话交接

> 手机版是**独立工程**：`cd mobile && npm install && npm run build && npm run serve`，
> 手机连同一 WiFi 打开终端打印的地址即可。
> 桌面版与它八竿子打不着，两个版本各自独立、互不影响。
