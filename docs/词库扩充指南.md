## 二、JSON 格式（一个文件 = 一个难度分区）

```json
{
  "level": 2,
  "note": "中频词（第 3 批）——四级常见、六级偏好",
  "words": [
    {
      "word": "abandon",
      "phonetic": "əˈbændən",
      "meaning": "v. 放弃；抛弃",
      "example": "He abandoned his car in the snow."
    }
  ]
}
```

字段要求：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `level` | 是 | 1/2/3，决定该文件所有词归到哪个难度 |
| `words[].word` | 是 | 单词原文，**全局去重依据**（不区分大小写的前后空格会被 trim） |
| `words[].phonetic` | 是 | 音标，不带两侧斜杠（前端会自己加 `/.../`） |
| `words[].meaning` | 是 | 中文释义，建议带词性前缀如 `v.` `n.` `adj.` |
| `words[].example` | 是 | 英文例句，一句话即可 |

⚠️ 注意：
- 文件是**严格 JSON**，不能写 `//` 注释，最后一个元素后面不能有逗号
- `meaning` 里如果出现双引号要转义 `\"`
- 同一关卡内的四个选项从同级别词库里随机取干扰项，所以**同级别词条越多，干扰项质量越好**

## 三、两种补词方式

### 方式 A：直接往内置文件里加（推荐，会重新打包进 exe）

1. 打开 `backend\src\main\resources\db\words-level2-b.json`
2. 在 `words` 数组末尾追加新条目（注意上一条后面补逗号）
3. 跑一遍去重脚本，确认这批新词真正进来了：
   ```bat
   cd /d <仓库根>
   node scripts\dedupe-words.mjs --fix
   node scripts\dedupe-words.mjs
   ```
4. 重新打包后端 + exe：`scripts\build-exe.bat`（只本地跑就直接 `mvn package`）

> 导入器**每次启动都会跑一遍增量补齐**，已存在的单词按文本去重跳过，所以：
> - 改完词库**不需要**删 `data\cet46.db`，重启就自动补上缺的词；
> - 旧版本只导入了一半词库、或导入中途被杀，重启就会自动补齐；
> - 补词只做 `INSERT`，**不会删除任何错题和学习记录**。
>
> 只有当词库严重错乱（分级混了、释义错位）时，才用「我的 → 词库维护 → 重置词库」（需两次确认，会清空全部学习数据）。

### 方式 B：外部词表追加导入（不重新打包，适合自己整理词表）

把自己的词表存成 JSON（格式同上，`level` 任意 1/2/3），启动时加参数：

```bat
cd /d <仓库根>\backend
C:\Program Files\Java\jdk-17\bin\java -jar target\cet46-word-platform.jar ^
  --import-words=D:/my-words/cet6-extra.json
```

特点：
- **已存在的单词自动跳过**（按单词文本去重），可以反复执行不怕重复
- 可以和正常启动参数共存；导入完成后服务正常启动
- 适合把网上找到的 CET4/CET6 词表（CSV 转 JSON 后）分批灌进来

## 四、从 CSV 批量转 JSON 的小脚本

如果手上的词表是 Excel/CSV（列顺序：单词,音标,释义,例句），在 `<仓库根>` 下建 `scripts\csv2json.mjs`：

```js
// 用法：node scripts/csv2json.mjs my.csv 2 > words-level2-c.json
import fs from 'node:fs'

const [file, level] = process.argv.slice(2)
const lines = fs.readFileSync(file, 'utf8').split(/\r?\n/).filter(Boolean)
const words = lines.slice(1).map((line) => {
  // 简单 CSV 解析：释义里可能有逗号，所以用最后一个逗号切例句
  const cells = line.split(',')
  return {
    word: cells[0].trim(),
    phonetic: (cells[1] || '').trim(),
    meaning: cells.slice(2, cells.length - 1).join(',').trim(),
    example: cells[cells.length - 1].trim()
  }
}).filter((w) => w.word && w.meaning)

console.log(JSON.stringify({ level: Number(level), note: '外部导入', words }, null, 2))
```

```bat
cd /d <仓库根>
node scripts\csv2json.mjs D:\my-words\cet6.csv 3 > D:\my-words\cet6.json
```

## 五、继续扩词的流程

新增一批词，固定这三步：

```bat
cd /d <仓库根>
node scripts\dedupe-words.mjs          :: 先看当前总量与各文件词数
:: 1. 新建 backend\src\main\resources\db\words-level3-n.json，写入新词条
node scripts\dedupe-words.mjs --fix    :: 全局去重，重复词从后加入的文件里删掉
node scripts\dedupe-words.mjs          :: 复查总数与分级分布
```

每补完一批，做四件事验收：
1. `mvn package` 重打 jar，删 `data\cet46.db` 后重跑后端，看启动日志的 `本次补齐 xxx 个单词` 与 `词库就绪：高频 / 中频 / 低频`
2. 访问 `http://127.0.0.1:8080/api/health`，确认 `wordCount` 与预期一致
3. 随便进一关，确认选项里没有重复释义、答案确实在选项中
4. 若只给已有库补词、不想删库：直接重启后端即可（自动增量补齐，不动学习记录）

> **补词方向很关键**：常用词早就高度覆盖了，后期批次重复率能到 90% 以上（实测一批 227 个常用词只留下 12 个）。继续补通用词纯属白做，有效的是**专业术语、学科词汇、政经法细分术语、书面语进阶词**这类“不常见但确实在大纲里”的词。

## 六、常见坑

| 现象 | 原因 |
| --- | --- |
| 启动日志显示本次补齐 0 个 | 词库已齐备，属正常状态（不是故障） |
| 重启后词数还是不够 | 确认 `words-*.json` 真的打进了 jar：`unzip -l backend\target\cet46-word-platform.jar | grep words-` |
| 后加的词把原有分级冲掉了 | 去重顺序问题。只能按文件 mtime 升序排，不能按文件名字典序 |
| 某关题目不足 20 道 | 该级别最后一关词数不满 20，属正常（`stageCount` 是向上取整） |
| 四个选项出现两个相同释义 | 同级别里有两个词释义完全一样。改一下其中一个的释义措辞即可 |
| 中文变成乱码 | JSON 文件必须存成 **UTF-8 无 BOM** |
